# 生产故障复盘（Incidents）

上线首日（2026-08-26）的真实事故记录。每条含：现象 / 根因 / 修复 / 回归断言位置。
这不是事后编的故事——所有条目都有 `runs/*.jsonl` 或评估结果文件可查。

## INC-01 LLM 输出 JSON 内嵌真实换行符

**现象**：前两轮生产运行（15:54、15:56）都在收尾步撞 `parse_error`——模型把
answer 写成多段落，JSON 字符串内含真实换行，属非法 JSON。

**根因**：`json.loads` 默认 `strict=True`，拒绝字符串内的控制字符。
LLM 天然倾向分段写作，输出"看起来对"但解析器不认。

**修复**：双管齐下。prompt 加规则"整个 JSON 必须单行，answer 内换行写 `\n`
转义"；解析器兜底 `json.loads(strict=False)` 容忍字符串内真实换行。

**回归**：`tests/test_parser.py` 形态1。

## INC-02 模型输出决策 JSON 后回声了对话上下文

**现象**：第三次运行（16:11）parse_error——模型输出完整决策 JSON 后，
把后面的工具结果块、助手标记也原样回声了出来。`first{ 到 last}` 的
粗暴截取把回声也吞了，解析必炸。

**根因**：单 prompt 渲染全对话（hermes CLI 通道无 role 结构）的固有弱点：
模型把 prompt 里的【用户】【助手】标记当成了要自己续写的格式。

**修复**：解析器改为"提取首个配平 JSON 对象"——状态机跟踪括号深度与
字符串转义状态，配平即截断，尾部回声天然丢弃。

**回归**：`tests/test_parser.py` 形态2。

## INC-03 漏数嵌套右括号（内容完整，括号缺失）

**现象**：002017 实战运行（16:54）收尾步 parse_error——答案内容写完整了
（结尾就是要求的数据来源行），但模型漏数了嵌套，右括号少写一个。

**根因**：LLM 对嵌套括号计数的经典失败。粗暴修法（末尾硬补 `}`）会误救
字符串中途截断的真残品——必须区分"内容完整缺括号"与"内容被切断"。

**修复**：`_autoclose_loads` 状态机扫到结尾——不在字符串内且深度>0 才补齐；
在字符串中途截断则不救，走重试路径（绝不产出半截答案）。过程中还发现
autoclose 在"一个右括号都没有"的场景没机会跑（rfind=-1），由新增的
测试用例当场抓出并修复。

**回归**：`tests/test_parser.py` 形态4/5（补齐恢复 / 截断不救）。

## INC-04 运行日志同秒文件碰撞

**现象**：002017 真实运行的日志文件里混入了并发测试进程的垃圾行——
同一个 jsonl 文件出现 5 个 meta 行（1 个真实任务 + 4 个 mock）。

**根因**：RunLog 文件名用秒级时间戳（`run_20260826_165406.jsonl`），
append 模式打开；真实运行与 `test_plumbing.py` 同秒启动，两个进程
写进了同一个文件。

**修复**：文件名追加 pid 后缀（`run_20260826_165406_193144.jsonl`）。
碰撞文件保留为 `runs/tests/collided_run_20260826_165406.jsonl` 标本。

**回归**：无（概率性问题），靠 pid 结构杜绝。

## INC-05 K线截断文案误导 agent 浪费步数

**现象**：002017 运行里 agent 调用 `get_kline` 后，被截断提示
"如需减少数据量可缩小 days 参数"误导，以为数据不全，缩小 days 重查
——白白浪费 2 步。

**根因**：进上下文的必须是消化过的东西。60 行原始明细表裸灌进上下文，
被截断闸腰斩；agent 只看到"只到5月底"的半截表。

**修复**：kline.py 统计摘要化——区间统计行（涨跌幅/高低点/分位/放量日）
+ 近10日明细带量比列，3000→821 字符（-73%），信息密度反而更高；
输出末行明示数据截至日期。这正是"上下文预算纪律"的落地。

**回归**：`tests/test_tools.py` + 真实运行上下文峰值观测
（峰值 2.5K~4.7K 字符，此前单 K线一项就 3-4K）。

## INC-06 工具结果驻留导致上下文线性膨胀

**现象**：量化发现 16 步任务终局上下文 36K 字符，其中工具结果占 86%。
hermes 通道每步全额重发，膨胀线性、成本线性。

**根因**：工具结果原文全程驻留 messages——设计上"一次任务"，实际上
第 10 步的 agent 还在背着第 1 步的 3000 字 K线表做决策。

**修复**：逐出机制 `evict_keep=3`——工具结果只保留最近 3 条原文，
更早的折叠为一行桩并明示"如需引用请重新调用该工具"（防 agent 误以为
数据还在）。16 步终局 36175→7085 字符（-80%）。每步 context_chars
记日志，效果可观测。

**回归**：`tests/test_plumbing.py` test_eviction / test_eviction_size_effect。

## INC-07 多轮指代消解"对但不点名"

**现象**：评估集 M2 首跑 FAIL——追问"它现在的估值在历史上算高吗"，
agent 指代消解实际正确（数据锚定全对：现价 11.73 正是第一轮的平安银行、
250 日 90% 分位算得也对），但回答文本没点明标的名称，coref 断言失败。

**根因**：能力缺陷 vs 可读性缺陷的鉴别——数据层面全对，问题只是
"人类读者不知道在说谁"。这是评估集存在的意义：抓出来的问题分两类，
一类改代码，一类改提示词。

**修复**：prompt 规则补"指代词须解析为具体标的并在回答开头点明"。
重验通过，且重验答案质量惊艳（年内分位[高]/深度破净[高]/多年维度
常识推断诚实标[低]，连年内低点 PE 换算都做了）。

**回归**：`eval/run_eval.py` M1/M2 用例（coref 断言保持严格）。

## INC-08 东财资金流接口只返回当日数据

**现象**：所有生产运行的"资金动向"节都是残的——接口只回当日 1 天，
agent 每次浪费 1-3 步重试不同 days 参数。

**根因**：东财对单 IP 间歇性限流，push2/push2his 直接断连，
push2delay 存活但个股/板块都只回当日——不是参数问题。

**修复**：三级 host 回退链 + 本地自累积缓存（`stockdata/fflow_cache.json`）：
接口给历史就刷缓存，只给当日就并入，全挂就回落缓存；输出末行标注
数据来源（"接口当日+本地累积缓存"），agent 如实转述，不把"只有一天数据"
包装成"趋势"。原子写（tmp+rename）防并发写坏缓存。

**回归**：`tests/test_tools.py` 断言输出含数据来源标注；评估集资金动向节
随缓存逐日增厚而改善（积累期观测项）。
